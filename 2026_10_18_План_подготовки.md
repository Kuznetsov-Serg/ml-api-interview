### 5. Анализ и оптимизация notebook'ов (3 кейса) 🔥 КЛЮЧЕВОЙ ПУНКТ
**Цель:** Показать умение оптимизировать "сырой" ML-код из Jupyter в production-ready решения.

**Кейсы:**

#### notebook_ml_1.ipynb (sklearn, iterrows)
- **Проблема 1:** `iterrows()` вместо vectorized operations
  - **Решение:** `df.apply()` или vectorized pandas
- **Проблема 2:** Загрузка модели в каждом запросе
  - **Решение:** Lazy loading в lifespan, singleton pattern
- **Проблема 3:** Нет типизации входных данных
  - **Решение:** Pydantic модели для валидации
- **Проблема 4:** Нет обработки ошибок
  - **Решение:** Try/except, graceful degradation

#### notebook_ml_2.ipynb (pandas, groupby)
- **Проблема 1:** Много промежуточных DataFrame
  - **Решение:** Chain operations, один agg с несколькими функциями
- **Проблема 2:** `apply(lambda)` вместо `np.where`
  - **Решение:** Vectorized conditions
- **Проблема 3:** CSV → запись в PostgreSQL без батчинга
  - **Решение:** `pd.to_sql()` с `chunksize`, async insert

#### notebook_ml_3.ipynb (LLM, streaming)
- **Проблема 1:** Модель загружается при каждом вызове
  - **Решение:** Lazy loading, singleton pattern
- **Проблема 2:** Обработка по одному тексту
  - **Решение:** Batching, SSE для streaming
- **Проблема 3:** Нет кэширования результатов
  - **Решение:** Redis cache с TTL

**Статус:** 🔲 Не начато
